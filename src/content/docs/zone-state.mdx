S3 keeps the history. DynamoDB answers the question “what is each zone doing
**right now**”. Every rule writes with `PutItem`, using the zone as the
partition key and the message kind as the sort key, so each new message
overwrites the last one of the same kind.

The <Tooltip term="iot-rule" label="IoT rule" /> `dynamoDBv2` action writes
each selected field as its own attribute
([DynamoDBv2 action](https://docs.aws.amazon.com/iot/latest/developerguide/dynamodb-v2-rule-action.html)).
The SQL must therefore produce the `thing` and `kind` keys itself.

## 1. Session variables

```bash frame="terminal"
set -a && source config/walkthrough.env && set +a
export GG_EDGE_ALLOW_AWS=1
AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
RULE_PREFIX=$(echo "${PROJECT_NAME}_${ENVIRONMENT}" | tr '-' '_')
IOT_RULE_ROLE="${PROJECT_NAME}-${ENVIRONMENT}-iot-rules"
IOT_RULE_ROLE_ARN=$(aws iam get-role --role-name "$IOT_RULE_ROLE" --query Role.Arn --output text)
ZONE_TABLE="${ZONE_TABLE:-${PROJECT_NAME}-${ENVIRONMENT}-zone-state}"
echo "$ZONE_TABLE"
```

```text
gg-edge-wt-dev-zone-state
```

The IoT rule role was created on [Archive telemetry](/archive/).

## 2. Table

### Create it (on-demand)

```bash frame="terminal"
aws dynamodb create-table --table-name "$ZONE_TABLE" \
  --attribute-definitions AttributeName=thing,AttributeType=S AttributeName=kind,AttributeType=S \
  --key-schema AttributeName=thing,KeyType=HASH AttributeName=kind,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST \
  --query TableDescription.TableStatus --output text
aws dynamodb wait table-exists --table-name "$ZONE_TABLE"
```

```text
CREATING
```

### Let the rule role write to it

```bash frame="terminal"
ZONE_TABLE_ARN=$(aws dynamodb describe-table --table-name "$ZONE_TABLE" \
  --query Table.TableArn --output text)
sed "s|ZONE_TABLE_ARN|${ZONE_TABLE_ARN}|g" artifacts/policies/iot-rule-dynamodb.json \
  > /tmp/iot-rule-dynamodb.json
aws iam put-role-policy --role-name "$IOT_RULE_ROLE" \
  --policy-name iot-rule-dynamodb --policy-document file:///tmp/iot-rule-dynamodb.json
```

```text
(no output)
```

## 3. Telemetry and actuator rules

[`telemetry-to-dynamodb.json`](https://github.com/jajera/aws-iot-greengrass-v2-edge-walkthrough/blob/main/artifacts/iot-rules/telemetry-to-dynamodb.json)
and
[`actuator-to-dynamodb.json`](https://github.com/jajera/aws-iot-greengrass-v2-edge-walkthrough/blob/main/artifacts/iot-rules/actuator-to-dynamodb.json)
take the zone name from `topic(3)`, the third topic segment.

```bash frame="terminal"
for r in telemetry actuator; do
  sed -e "s|ZONE_TABLE|${ZONE_TABLE}|g" -e "s|IOT_RULE_ROLE_ARN|${IOT_RULE_ROLE_ARN}|g" \
    "artifacts/iot-rules/${r}-to-dynamodb.json" > "/tmp/rule-${r}-ddb.json"
  aws iot create-topic-rule --rule-name "${RULE_PREFIX}_${r}_ddb" \
    --topic-rule-payload "file:///tmp/rule-${r}-ddb.json"
done
```

```text
(no output)
```

## 4. Read the greenhouse

### Latest telemetry per zone

```bash frame="terminal"
sleep 15
aws dynamodb scan --table-name "$ZONE_TABLE" \
  --filter-expression "#k = :k" --expression-attribute-names '{"#k":"kind"}' \
  --expression-attribute-values '{":k":{"S":"telemetry"}}' \
  --query "Items[].[thing.S,tempC.N,rssi.N,uptimeS.N,rgb.S]" --output table
```

```text
----------------------------------------------------------
|                          Scan                          |
+-------------------------+-------+------+-------+-------+
|  gg-edge-wt-dev-esp32-2 |  26.5 |  -28 |  7053 |  off  |
|  gg-edge-wt-dev-esp32-1 |  29.9 |  -28 |  7053 |  off  |
+-------------------------+-------+------+-------+-------+
```

Keep each zone’s `tempC`. [Raise an alarm](/alarm/) sets its threshold relative
to this baseline.

### Who drove the RGB last

Press and release **BOOT** on `esp32-1`, then:

```bash frame="terminal"
aws dynamodb get-item --table-name "$ZONE_TABLE" \
  --key "{\"thing\":{\"S\":\"${CLIENT_THING_NAME}\"},\"kind\":{\"S\":\"actuator\"}}" \
  --query "Item.{state:state.S,color:color.S,source:source.S}"
```

```text
{
    "state": "off",
    "color": "green",
    "source": "com.example.GgEdgeLoop"
}
```

`off` is the release. Holding the button while you run the command shows `on`.
On the next pages the same item records `source: cloud` (blue) and
`source: com.example.ZoneAnomaly` (red). One table holds the audit of which
layer acted.

If `actuator` never appears but `telemetry` does, confirm the deployment has
`ActuatorPubsubToIotCore`.
